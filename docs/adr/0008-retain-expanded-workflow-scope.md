# Retain expanded capability contracts beyond the static facade

<a id="adr-0008"></a>

## Decision

- Retain value-dependent composition/homogeneous traversal, arbitrary typed local fragments, children, approvals, historical forks, post-success compensation authority, shared capacity, halt/resume, richer introspection, reducers, and undo retry/supervision decisions.
- Retain registered runtime graphs with finite Blueprint contracts, parametric nodes, conservative exact compatibility, publication/retirement, native adapters, LLM/Fabric composition, visual tooling, and persistence.
- These are intended capabilities; current static/checkpoint implementation remains authoritative for delivered behavior. Authority/race, broader assignability, migration, and retirement policy require separate rulings.

## Rationale and alternatives

- Reducing scope to current functions loses accepted intent. Copying obsolete laboratory signatures fabricates runtime guarantees.
- Runtime contracts validate values after compilation and cannot create new native types. Registered runtime graphs preserve that separate boundary.
- Child success or copyable receipts cannot establish exclusive compensation authority; owner/storage must authorize and deduplicate.
